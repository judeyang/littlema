## 1. 推荐决策

把当前“关数越高，棋盘越大、档位越高”的规则，替换为“长期缓慢变难，短期有挑战、有缓和”的关卡编排。每道题先通过正确性检查，再根据实际推理过程评估难度，最后安排到合适的关数。

核心体验：学会一种关系 → 独立发现它 → 用它破解挑战 → 在轻松关感受到熟练 → 再遇到新的组合。

同时设计两个尺度：关与关之间有张弛；一关内部有入口、思考、突破后的顺畅推进和收尾。目标是让玩家感到“有点难，但我想通了，而且我变厉害了”，并满意地结束、愿意再次回来。游玩时长与继续点击不作为多巴胺变化的测量指标。

建议确定以下方向：

1. 第 1～3 关可以保留一个单格区域教学；第 4～8 关逐步退出；第 9 关起，主线新题不再含原始单格区域。后期缓和关也通过较少的推理转折来降难度。
2. 明显挑战间隔约 4～6 关；挑战后安排一关压力明显下降、复用刚学技巧的题。首批 30 关采用固定约 5 关的基准间隔，验证后扩充不同节奏模板。
3. 棋盘尺寸与推理难度独立。允许难的 7×7，也允许舒缓的 9×9；保留 11×11、12×12 能力，但不再作为高关数的必选项。
4. 高难来自必须找到的关系及其证明复杂度。短挑战关可以只有一个精彩难点；较长挑战关才安排多个分离的难点，突破后留出顺畅推进。唯一解、可解释推理是入库条件。
5. 提示输出“观察对象、成立原因、具体结论”，支持分层展开。提示要能解释复杂推理，文字本身仍应清楚。
6. 首版采用预先生成并验证的关卡库。正式游玩优先取题，不在点击下一关时反复同步造题。

本方案形成于代码修改前；其后已开始实施，底座与题源验证见 docs/production-audit.md。方案中的难度数值、节奏目标、性能目标仍是待校准的设计参数，不是已经验证的玩家表现。

本轮修订同步覆盖前 30 关、单关节奏、评分与内容准入、提示、实施阶段和试玩验收。原始诊断数据保持其检查时点含义，不作为新设计已生效的证据。

## 4. 关卡节奏：缓慢上升的波浪

### 4.1 编排原则

- 难度由关卡自身的推理证据决定；编排器负责选择符合当前节奏的题。
- “舒缓、推进、小峰、峰值”等词仅用于策划标注，不变成普通／技巧／大师三种永久关卡类别。
- 一次挑战成功后，下一关要有可感知的压力回落，并复用挑战中的关键技巧。通过更清晰的布局、较少的关系组合和较短的流程，让玩家感受到熟练。
- 一组新技巧先在低观察负担的题中出现，再以复杂布局考察；学习新技巧、放大棋盘、加深推理不同时发生。
- 高峰间隔约 4～6 关；首版固定基准验证，之后从经过审查的模板选取。首个教学挑战不受前序峰值间隔约束。

### 4.3 第 11 关以后的基准计算方式

初始 10 关用上表手工配置。之后以 10 关为一个周期：

```text
cycle = floor((level - 11) / 10)
slot = (level - 11) % 10
baseline = min(60, 34 + 5 * cycle)
offsets = [-12, -4, +3, +12, -10, -2, +7, +4, +20, -13]
target = clamp(baseline + offsets[slot], 0, 100)
```

基准模板中第 14、19、24、29……关形成峰值，之后一关降压。此公式用于首轮对照，不是所有后续版本固定每 5 关出峰的要求。基准达到上限后，用题型组合、关系位置和关卡内容变化保持新鲜感，不持续把难度推向不可完成。

尺寸选择独立从已验证题库中取。先以 6×6～9×9 为主；10×10～12×12 的频率依据实际操作体验与题库质量决定。大棋盘候选不足时允许选择同难度的小棋盘，不允许悄悄降低逻辑要求。

### 4.4 单关内部：突破之后有成果

推荐形态：找到入口 → 可完成的推进 → 关键关系 → 突破 → 连续完成几步 → 收尾。允许短题直接从关键入口开始，只要入口可观察且证据可解释；不要求每关先送出一匹马。

- **短挑战题**：一个有分量的关键证明即可，之后允许基础推理解完整盘。是否有挑战取决于关键证明本身，不因只有一个瓶颈而拒绝。
- **较长挑战题**：初设 2～3 个分离瓶颈，必要时最多 4 个；瓶颈间安排可连续完成的有效标记或落马，避免每一步都需要重新苦思。
- **舒缓题**：复用已经引入的关系，缩小观察范围、减少前提和流程；零单格同样可以顺畅。
- **收尾**：通常用已经建立的事实结束，不在最后一匹马突然加入全新规则。

比如发现“三区域占三列”后，排除一组格、确定一匹马，再顺势确定另外两匹马。这些后续进展是突破的成果，不要求玩家每次都重新付出同等思考成本。

生成器记录瓶颈与后续推进段的完整轨迹。只有复杂技巧堆积、缺乏推进段的题不优先入选主线；一个明显锁列后一路结束的题可进入舒缓位，一个复杂而优美的关键证明后一路结束的题仍可进入短挑战位。

### 4.5 跨关学习与变化模板

同一技巧按“清晰示范 → 独立辨认 → 组合挑战 → 清晰短题巩固 → 新组合”安排。教学关先于要求独立完成的新技巧挑战关，缓和关通过题目自身体现学习成果。

首批 30 关完成固定节奏试玩后，可采用以下模板：

| 模板 | 周期内安排 | 用途 |
| --- | --- | --- |
| A，5 关 | 顺畅 → 推进 → 挑战 → 缓和 → 巩固 | 标准短周期 |
| B，5 关 | 热身 → 推进 → 巩固 → 挑战 → 缓和 | 多一关准备后再挑战 |
| C，6 关 | 推进 → 小挑战 → 缓和 → 推进 → 大挑战 → 缓和 | 较长学习周期；小挑战不算明显峰值 |

模板不是任意拼接：编排器必须检查上一段最后一个明显峰值与下一段第一个峰值，实际间隔保持 4～6 关，并保证每个明显峰值后有缓和。第一批固定主线不随机改变，扩展模板的选择与结果随 campaignVersion 固定保存，方便复盘。

每个关卡槽位记录：targetScore、allowedRules、introducedRules、practiceRules、recoveryOfLevel、challengeShape（短关键题／较长组合题）及目标推进段。recoveryOfLevel 关联具体挑战关与待复习技巧，不只关联一个较低分数。首次引入技巧时保持前关尺寸，不同时提高观察复杂度或假设深度。

## 5. 怎样衡量“真正难”

### 5.1 先设正确性门槛

每道正式题必须满足：

1. n×n 个格，恰好 n 个非空区域；每区域四邻接连通。
2. 行、列、区域各一匹马，马之间八邻域不相邻。不是传统皇后的整条对角线禁放。
3. 独立精确求解器确认恰好一个解；计数达到两个立即拒绝。超时返回 unknown，不当作唯一解。
4. 已公开支持的人类推理规则可以完整解出，并能逐步回放证据。
5. 不超出本关已引入的技巧范围和允许的反证复杂度。
6. 满足单格限制、目标分区间、关卡瓶颈、重复度等编排条件。

“有唯一解”不能代替“人能按规则推出来”；“求解器用了一个高级规则”也不能直接代替“高级规则确实有必要”。

### 5.2 记录难度画像

| 字段 | 定义 | 用途 |
| --- | --- | --- |
| singletonCount | 开局原始单格区域数 | 第 9 关起必须为 0 |
| basicClosureSolvedRatio | 从空白开始，只用唯一候选和已确定马排除，直到不再变化，确定马数/n | 识别一眼起手后一路推完的题 |
| cascadeAfterBreakthrough | 每次非基础突破后，仅用基础规则还能确定的马数/n；记录最大值与各段分布 | 零单格题也可能一次转弯后整盘自动展开，用此指标识别 |
| requiredRuleTier | 分别限制规则集跑到不动，找到能够完整解出的最低支持层级 | 区别“可用高级规则”与“较弱规则不够” |
| openingProof | 第一处有效推进的规则、前提、观察范围 | 保证零单格题有可解释的入口 |
| bottleneckEpisodes | 基础规则耗尽后，至少使用一次非基础推理才重新推进的阶段数 | 区别一次转弯与多次卡点 |
| bottleneckPositions | 每个瓶颈发生时已完成的马数/n | 避免所有难点都堆在开头或末尾 |
| progressSegments | 每次关键证明后可连续完成的有效标记、落马及其依赖轨迹 | 评估突破后的成果，不把原始点击次数当奖励 |
| challengeShape | 短关键题或较长组合题，由策划声明并由轨迹审查 | 分别审查瓶颈数量和推进段，避免统一要求多瓶颈 |
| proofDepth / premiseCount | 最难一步依赖的推理层数、前提数 | 区别简单长流程与复杂推理链 |
| lookaheadDepth | 假设嵌套层数；首版最多 1 | 控制反证认知负担 |
| forcedStepsInHypothesis | 单次假设后必须展开的步骤数 | 首版峰值初设不超过 3 步 |
| usefulMovesAtStall | 卡点状态下可用的新推理数量，重复结论去重 | 估计突破口多少 |
| focusRegionCount / span | 关键证明要同时关注多少区域、多大范围 | 估计观察负担 |
| workUnits | 有效标记、确认及证明步数量 | 记录操作量，低权重进入难度 |
| signature | 规范化盘面与推理结构签名 | 防止换色、旋转、镜像冒充新题 |

基础闭包必须穷尽所有基础规则，再记录卡点。连续放出多匹马只说明连锁长，不能把每匹马都算一次高级瓶颈。同一“三区占三行”一次消掉 12 格，也只能算一个逻辑事件。

第 9 关后取消原始单格时，空白盘面的 basicClosureSolvedRatio 通常为 0，不能再靠它区分题目。此后应结合关键证明的分量、后续连锁比例与单关形态判断。明显锁列后一路到底适合舒缓；复杂关键证明后顺畅收尾可以成为短挑战。连锁本身既不是加难依据，也不是拒绝挑战题的理由。

### 5.3 初始评分器

先输出完整画像，再给排序用的 0～100 分。评分初稿：

```text
D = round(100 * (0.40*R + 0.10*B + 0.30*P + 0.15*S + 0.05*W))
```

- R：最低必要规则层级归一化，基础唯一候选为 0，单锁／双锁／三四区联合／共同冲突／短反证逐步提高。具体排序通过试玩校准。
- B：瓶颈阶段数量，初始用 min(episodes/4,1)，权重降到 10%。瓶颈分布与推进段另作内容质量审查，不用堆瓶颈提高题目评级。
- P：最难一步的证明依赖复杂度，结合前提数量、推理深度和假设后的传播长度；普通基础连锁不能累加到最高档。
- S：观察负担，结合涉及区域数和可见推进数量，先用固定数据集分位归一化。
- W：操作量归一化，最多占 5%；尺寸本身不额外加分。

本轮提高关键规则和证明复杂度的权重，降低瓶颈数量的权重，让单个精彩难点有机会成为短挑战。评分用于候选排序，单关节奏与学习配对作为独立准入条件；不能靠高分补偿没有推进段的疲劳体验。前 30 关目标分仍是策划初值，需用更新后的评分器重新标定，不代表现有题已命中。

所有归一化边界随评分器版本冻结。新增题不能临时改变整个题库的分位数，否则旧关难度会漂移。

自动评分是代理指标，尤其是规则先后顺序与观察难度带有经验性。需要让用户及真实玩家评价，不能把分数描述成客观心理测量。

用于 requiredRuleTier 的规则集合必须逐层包含前一层，形成固定能力阶梯。某两种技巧认知难度相近时可放在同层，不强行认为四区联合一定比短反证简单。若策划指定“必须用某一种技巧”，还要单独移除该规则族检查其他已支持规则是否仍能解完，不能从层级分数反推某规则必需。

### 5.4 防止“高级规则装饰品”

入库至少跑三类分析：

1. 限制较弱规则集，穷尽推理；若依然能解完，不得认定更强规则必要。
2. 在卡点尝试不同合法推进顺序，取找到的较容易路径评分，避免只凭一种固定顺序人为抬高难度。
3. 检查旋转、镜像后分数是否异常变化；明显变化通常说明扫描顺序偏差。

首版可对卡点保留最多 8 条候选路径、最多 200 次状态展开，超出预算记为分析未完成。受限路径搜索只证明“已检查路径中的情况”，不宣称全局最短或唯一推理路径。强制要求某技巧时，以更弱规则集的完整闭包停滞为证据；做不到完整检查的题暂不安排在指定技巧挑战位。

### 5.5 峰值题的硬条件

- 原始单格区域为 0。
- 至少一个真正的非基础瓶颈。短挑战题可只有一个关键难点；较长挑战题初设 2～3 个，最多 4 个，中盘至少有一个，瓶颈之间有有效推进段。
- 使用该关已经教学过的规则。挑战的是辨认和组合，不突然要求未讲过的知识。
- 至少一处比当前舒缓题明显复杂的证据关系，或者更多相互分离的瓶颈。
- 在可选分支试探中首版最多一层假设，展开不超过 3 个解释步骤；超限题留在开发池。
- 支持完整提示回放；不能出现“只有读取答案才知道下一步”的正式题。
- 通关后的缓和题复用本关关键技巧，降低观察或组合负担；不能仅通过缩小棋盘或送单格答案完成配对。

## 6. 统一的人类推理规则库

### 6.1 首版规则

| 规则 ID | 成立条件与结论 | 提示重点 |
| --- | --- | --- |
| single | 未满足的某行、列、区域只剩一个可信候选 | 为什么其他候选不成立 |
| placed-exclusion | 已确认的马排除同行、同列、同区和相邻其他格 | 展示这匹马及一类冲突范围 |
| region-line-lock | 某未满足区域的全部候选落在同一行／列 | 该行／列的名额已被该区域占用 |
| line-region-lock | 某未满足行／列全部候选属于同一区域 | 该区域的马必须在这行／列，其余区域内格可排除 |
| region-subset-lock | k 个未满足区域的候选合计只覆盖 k 行／列，k=2～4 | k 匹马必须占 k 条线，线内其他区域排除 |
| line-subset-lock | k 条未满足行／列的候选合计只属于 k 个区域 | 这 k 个区域的名额在这些行／列内，区域外侧候选排除 |
| common-conflict | 一个必有马的组，无论选哪个候选，都与某格冲突 | 展示所有备选共享的冲突格；包含适用的 L 形特例 |
| bounded-contradiction | 假设某格有马，经过限定规则传播，某个必有马的组清零或产生确定冲突 | 明确假设、每步传播、具体矛盾，撤销假设后排除该格 |

行列两个方向分别尝试；不能因行方向符合结构却没有新排除，就遗漏列方向的有效结论。所有规则只返回新的有效结论，不能对已满足组重复计数或把马自身排除。

共同冲突规则可理解为：一个区域还有两个位置 A、B，不论马在 A 还是 B，格 X 都会与它相撞，所以 X 可以排除。它不需要先猜出马在哪儿，比笼统的“反证一下”更容易解释。

### 6.2 三种求解能力分工

- 精确求解器：检查解数、测试某结论的反例是否存在，作为开发验证裁判。
- 人类推理引擎：只读取盘面、可信事实和规则；输出每一步证明，供评分与提示共同调用。
- 关卡编排器：根据分析报告选择关卡，不参与推理。

提示生成接口不接收隐藏答案数组。游戏判对错仍可使用答案；测试裁判也可使用答案。必须从接口上保证“判断答案”和“解释答案”没有混在一起。

## 7. 新提示体验

### 7.1 同一步分三层，逐渐揭示

1. **看哪里**：指出值得观察的区域或行列，不直接标出答案格。
2. **为什么**：解释数量关系或冲突，并高亮证据。
3. **下一步**：展示准确可排除或可放马的目标。

例如参考 IMG_7481 的两区域占两行：

> 看哪里：观察最上面的青色和杏色区域，它们的小马会出现在哪几行？
>
> 为什么：这两个区域各要放一匹马，它们的候选都在第 1、2 行。两匹马不能同一行，所以这两行的名额都被它们占用了。
>
> 下一步：第 1、2 行里其他颜色的高亮格可以排除。

“思路 → 解释 → 结论”围绕同一条证明递进。用户没操作棋盘时，不因再次点击而随机换一条提示。

玩家可以在第一层或第二层关闭提示后自行推进；也可以直接请求完整解释，不设置等待门槛。第一层可以用“这三个区域的候选一共分布在几列？”这样的观察问题，第二层必须给出清楚理由，不能把难懂的文案当作挑战。记录实际展开的最高层级，便于后续识别是否学会该关系。

### 7.2 画面组织

- 提示期间压暗无关区域，保留盘面位置与格子尺寸。
- 证据格用实线轮廓和编号；结论格用虚线轮廓、✕ 预览或马轮廓。不能只靠颜色区分。
- 行列范围加括号或边缘标签；写明第几行、第几列，不只说“这几行”。
- 三四个区域联合时用颜色小样＋区域名称／编号，避免一长串颜色名挤进提示气泡。
- 解释卡保持到用户关闭，可返回上一层；不再依赖几秒后消失的 toast 承载复杂推理。
- 复杂反证逐步显示：“假设这里有马 → 这些位置被排除 → 指定区域无候选 → 假设不成立”。假设态只在提示层模拟，不写入正式棋盘。
- 有明显简单推进时，优先提示简单步骤。高关卡不强制输出四区域联合，否则会制造不必要的认知负担。

### 7.3 关于“快速应用”

首版默认仅展示思路和结论，由玩家操作。保留“应用这一步”作为可选辅助设计，默认关闭，未来可在设置中开启；截图中的按钮不自动等于本项目需求。

若实现：只在用户已经展开第三层后显示，执行当前这条证明的结果，整个步骤可一次撤销；不会自动连着解下一步。应用前校验当前盘面版本，过期提示不得执行。是否自动放马与是否批量标 ✕ 分开设置。

保留“显示解”的求助用途，但与推理提示明显区分；看过答案的通关记录为辅助完成，避免用它判断玩家水平。

### 7.4 错误标记处理

运行状态区分：

- confirmed：游戏已确认的马。
- knownEmpty：已经翻错、确定为空的格。
- userMarks：玩家手动 ✕，可能正确也可能错误。
- deductions：由可信事实和规则推出的排除与确定位置，带证明来源。

手动 ✕ 不直接成为逻辑前提。重新推理时从 confirmed、knownEmpty 和规则重建可信结论；玩家已经正确标记的结论可不重复作为操作目标，但其必要前提仍可在解释中显示。

如果可信推理证明某个手动 ✕ 位置有马，先解释并建议撤销该标记。如果只能发现“一组候选被全部手动排除”，只能说这组标记有矛盾，不凭猜测指认哪一个错误。无法给出短证明时明确显示当前解释限制，不能查隐藏答案后冒充推理。

允许导出当前 puzzleId、局面和诊断结果用于复现，但不自动上传。

### 7.5 提示数据契约（建议）

```ts
type ProofStep = {
  id: string;
  ruleId: string;
  premises: FactRef[];             // 可引用此前步骤，必须可展开
  sourceCells: number[];
  groups: GroupRef[];             // 行、列、区域；统一零基索引
  conclusion: { place: number[]; exclude: number[] };
  contradiction?: {
    assumedCell: number;
    steps: ProofStep[];
    conflictGroup: GroupRef;
  };
};

type Hint = {
  puzzleId: string;
  stateRevision: number;
  proof: ProofStep;
  level: 1 | 2 | 3;
  focus: { evidenceCells: number[]; targetCells: number[] };
};
```

文案按 ruleId 和结构化事实生成，不把“自然语言看起来合理”当作证明。中文排版、颜色名称、行列编号在格式化层统一处理。UI 显示一基编号，测试统一检查索引转换。

### 7.6 突破反馈与能力感

反馈紧扣已经发生的事实：放对马给轻量确认、相关计数更新；使用提示完成关键一步后，可简短总结“这三个区域的限制，排除了这几列的其他候选”。不为每次标记弹出泛化夸奖，不以额外动画中断突破后的连续操作。

玩家自由标记可能存在多种合法思路。没有提示轨迹或其他可靠证据时，不宣称系统知道玩家用了哪一种技巧；可说“这一片的马已经全部找到”，不能凭落子序列断言“你掌握了四区域联合锁”。独立完成与技巧掌握也应分别记录。

关卡结束保留明确的继续入口和可自然离开的状态，进度自动保存。玩家是否愿意回来与是否满意，比强行延长本次会话更适合作为本项目体验评价。

## 8. 生成器与关卡库

### 8.1 推荐管线

```text
目标关卡规格
  → 候选盘面生成／结构模板变体
  → 独立唯一解与区域合法性检查
  → 人类规则求解及证据回放
  → 难度画像与多路径检查
  → 去重与节奏匹配
  → 已验证关卡库
  → 浏览器按关数读取
```

### 8.2 保留什么、替换什么

现有小马位置回溯、四邻接检查、整体变换可以复用。基础构造器用于教学及舒缓候选，不再承担所有难题的起点。

候选题提供两条来源，先试验后决定比例：

1. **带逻辑结构的种子题**：以单区域锁、两区占两线、三四区联合、共同冲突等为设计起点，构造连通区域，完整求解验证。模板只是候选来源，不保证自动成功。
2. **目标约束下的区域搜索**：移动边界格、小片区交换、重新分配局部区域，以零单格、唯一解、目标瓶颈与去重为目标。保持马位置和区域连通；批次末独立验证。

现有逐步扰动要求每一次变动都立即可被旧求解器解出，会限制能到达的题型。新离线搜索可允许中间状态暂时不满足人类可解门槛，但最终入库必须通过全部门槛，且不得在游玩时暴露中间态。

先做小规模产题试验，关注接受率、题型多样性与耗时，分别产出零单格舒缓题、单关键难点短题、带推进段的多瓶颈长题。如果任一目标类别难以稳定产出，优先手工设计并审校种子题，不继续盲目增加随机重试次数。

### 8.3 关卡资源结构

```ts
type PuzzleRecord = {
  puzzleId: string;
  contentVersion: string;
  generatorVersion: string;
  seed: number;
  size: number;
  regions: number[];
  solution: number[];       // 供判题；不会传入提示引擎
  analysis: {
    analyzerVersion: string;
    unique: true;
    humanSolvable: true;
    difficultyScore: number;
    profile: DifficultyProfile;
  };
  signature: string;
};
```

关卡表独立维护 level → puzzleId／候选集合、目标画像及技巧解锁，包含第 4.5 节的学习配对字段和 campaignVersion。关卡角色属于编排表，同一道题对不同经验玩家的作用可以不同，不把舒缓／挑战作为题目不可更改的永久属性。第 1～30 关先固定选题，再扩大到 100 关。资源按块加载，长证明轨迹留在开发产物；线上保留必要分析摘要，并由共享引擎按当前局面生成提示。

### 8.4 重玩、进度与版本

- “重玩本关”重置同一 puzzleId；“换一道同难度题”作为另一个明确操作，才允许换题。
- 刷新恢复 level、puzzleId、内容版本、已揭示马、误点、标记与辅助记录。
- 载入时检查边界、区域和局面合法性；存档损坏时提示并安全退回当前关起点，不静默清空全部记录。
- 更新题库时，正在玩的题保持原版本；跨关才采用新的资源。
- 相同 seed 还必须配合相同生成器版本与配置才能复现，不能只存 seed。
- 旋转、镜像和换色统一计算规范化签名，避免连续关遇到同一道本质相同的题。

### 8.5 失败回退

产题预算耗尽：输出明确失败原因和画像差距。正式游戏优先使用已验证的同目标备用题；没有备用题时提示资源未就绪或加载失败并允许重试，不把容易题标作挑战题。

后续需要动态新题时放入 Web Worker，设超时与取消标记；生成器版本和关卡请求版本绑定，旧结果不能覆盖新的局面。首版不以运行时随机生成作为上线依赖。

## 9. 实施模块与依赖顺序

保持原生 JavaScript，首版不引入框架、后端或数据库。因当前是可直接打开的静态页面，模块拆分采用浏览器与 Node 均可访问的纯 JS 导出约定，并明确脚本加载顺序；若改用原生 ES Modules，应同步提供 localhost 启动方式和 README，不无声破坏原来的文件打开方式。

## 10. 分阶段实施与验收

### P0：冻结样本，建立正确性底座

工作：冻结本次代码摘要和错误状态；补齐项目文档入口；实现不读取答案的精确解数检查；整理规则定义并移除 T10 的虚假能力声明。

产物：固定题目 fixture、解数检查器、输入校验、当前行为基线、实施 ROADMAP。

验收：无解、多解、唯一解三类测试能正确区分；超时是 unknown；已知提示错误 fixture 可稳定复现；不把源代码中的答案数组当作唯一性证明。

### P1：统一证明引擎

工作：从基础规则、双向锁行列到 k=2～4 联合锁，逐个建立结构化证明；接入共同冲突和限定反证；统一可信状态；用引擎替代生成校验和提示中的重复逻辑。

产物：共享 logic-engine、ProofStep、证明回放、错误标记修复提示。

验收：每条规则有正例、反例、边界例；每条排除用独立裁判验证“在该格放马无可行解”；每条确定用独立裁判验证“排除该格无可行解”；裁判不能参与生成解释。

额外检查：每条证明前提必须对应当前可信局面；不能只验证结论碰巧符合答案。已确认的提示错误 fixture 不再产生错误排除。

### P2：难度画像与产题可行性试验

工作：实现基础闭包、最低支持规则层级、瓶颈、突破后推进段、短反证复杂度和去重；先对 6×6～9×9 产题，比较结构模板与区域搜索。分别审查关键证明复杂度与流程长度。

产物：首批 30 道可比较样题，覆盖零单格舒缓题、单关键难点短挑战和多瓶颈长挑战；包含同技巧挑战／缓和配对，逐题附分析证据。

验收：至少形成数对同尺寸但不同推理难度的题；挑战题不能仅靠基础规则解完；短挑战不能因只有一个瓶颈而被机械拒绝，较长题必须审查瓶颈间推进段；弱规则闭包、完整求解及多方向检查结果可复现。若产出不足，暂停扩到 100 关，先修题源。

### P3：落地 30 关波浪编排

工作：按第 4 节初稿选题；检查教学先于独立挑战、挑战与同技巧缓和配对、尺寸和难度分布；实现同题重玩、进度保存及版本固定。先采用固定基准模板，扩展模板仍须审查跨周期边界。

产物：固定 30 关主线、备用题清单、明确的关卡内容版本。

验收：峰值后必有明显下降且复用本轮技巧；没有连续峰值；第 9 关起零原始单格；新技巧不与棋盘扩容同时引入；挑战位按长短形态满足硬要求；刷新／失败重试恢复同一道题；切关不残留旧提示和长按状态。

### P4：提示界面与可读性

工作：三层展开、证据／目标差异化、行列标识、可关闭说明卡、假设逐步演示、轻量突破反馈及提示层级记录。可选“应用这一步”单独实现，不作为默认验收前提。

产物：可以解释单锁、2～4 区联合、共同冲突、短反证和纠错的提示界面。

验收：从卡点点提示 → 看范围 → 看原因 → 看目标 → 关闭后继续；也支持在第一／二层提前退出自行推进，或直接展开完整解释；提示不自动修改棋盘；无新结论时说明真实状态，不无条件要求“先翻开已确定的小马”；提示显示期间换关、清除、落子后旧版本作废。自主落子反馈不得无证据认定玩家使用的技巧。

### P5：真实试玩校准，扩展到 100 关

工作：先请主人做同尺寸易／难题盲测，再找 6～10 名不同经验玩家做小规模试玩。先准备两个独立任务块：盲测块交错安排易／难题，比较难度差异；主线块保留教学、挑战、同技巧巩固的完整顺序，验证节奏与学习迁移。不能把主线全部打乱后仍宣称验证了成长体验。

每人先玩 12～20 关或分次完成，避免疲劳扭曲结果。小样本只做方向性校准，不做统计显著性宣传。记录时长、错误、提示层级、突破后推进、完成与放弃、主观难度、有趣程度及满意度，按经验分组。

| 指标 | 首版记录口径 | 用来判断什么 |
| --- | --- | --- |
| 首次无提示完成率 | 首次进入该题，未展开提示、未看答案、未应用辅助即完成；分组报告完成数与首次进入数 | 难度是否适合该经验群体；不是必须制造失败的配额 |
| 突破后推进 | 证明轨迹预测的推进段，结合试玩操作和简短访谈核对 | 想通后是否有可感知的成果；点击间隔只能作为辅助线索 |
| 提示后的迁移 | 比较不同 puzzleId 的同技巧题，记录最高提示层级、错误与独立完成情况 | 下一道类似题是否更少依赖帮助；重复同题不作为独立证据 |
| 主观体验 | 询问有挑战／看不懂／只能猜、是否能说清关键理由、是否感觉更熟练 | 长时间是否真的带来成就感 |
| 满意后的回访 | 在已说明记录目的的试玩中，询问结束满意度，并记录观察期内是否自愿再次体验 | 游戏是否值得回来；离开不自动判作失败 |

记录保存为本地或人工试玩数据，不自动上传。最小记录包含 puzzleId、contentVersion、campaignVersion、attempt、前后台时间段、提示 proofId 与最高展开层级、辅助状态、完成状态和问卷回答。技巧使用必须区分证明可观察事实与推测，不能从用户没点提示直接推出已掌握。

时长排除明确的后台和主动暂停时间；前台长时间没有点击可能正在思考，不自动扣除，也不直接判为卡住。放弃、暂停和恢复分开记录，不把未完成样本从报告中删掉。

挑战题活跃时长约为舒缓题 1.5～2.5 倍，可作为探索性观察区间，不能成为硬门槛。精彩短挑战即使耗时较短也可以成立；如果时间增加伴随错误、求助和不满，应检查题目与提示，而不是把变长视为成功。不设置“最佳多巴胺分数”或统一 85% 通关率目标，研究边界见第 14 节。

产物：更新的评分器、已校准 30 关、同规范扩展到 100 关的题库与版本记录。

验收：用户能辨认张弛节奏，短挑战和长挑战都能产生“能想通、解开有成就感”；突破后有顺畅推进；同技巧巩固题能表现出较少提示依赖或更清楚的理由复述。对每个挑战／缓和配对保留数据及继续采用、修改或淘汰的决定。若时间变长却主要来自密集点击或困惑，应修订题目；若学习迁移证据不足，标为待校准，不以较长时长替代。回访仅作辅助信号，不因少量样本未回访就判定方案失败。

## 11. 测试清单与失败路径

### 数学与规则

- 非法 n、regions 长度错误、区域越界／为空／不连通、重复行列马、相邻马。
- 无解、多解、唯一解、解数搜索超时；错误答案数组不能让错误题入库。
- k 区域恰好覆盖 k 行时有效；任一区域还有候选在第 k+1 行时不得触发。
- 行方向无新结论而列方向有结论；k 个区域不可包含已满足区域重复占名额。
- 反证区分行无候选、列无候选、区域无候选；文案必须与实际冲突对象一致。
- 在整个首版题库回放所有证明；额外对至少 1,000 个固定种子候选题及其变换做自动检查，全部报告失败样本，不能只输出通过数量。
- 随机加入正确与错误用户标记，检查无错误落马、无错误排除、无 mutation 泄漏；测试包含本次已复现 fixture。

### 节奏与资源

- 1、3、4、8、9、10、11、14、15、19、20、29、30、31 等边界正确。
- 前 100 关峰值间隔、回落幅度、尺寸变化和规则引入顺序可自动审查。
- 跨模板拼接仍满足明显峰值间隔 4～6 关；较小起伏不误算峰值；首个教学挑战单独处理。
- 每个 recoveryOfLevel 指向存在的前序挑战，practiceRules 包含待巩固关系；降低一个维度的同时，不引入未教学规则。
- 短挑战的单关键证明可以入库，长挑战的连续瓶颈却没有推进段时必须提示审查；不按单一瓶颈数量阈值处理所有题。
- 分数合格但有单格／缺必要技巧的题，仍应拒绝。
- 题库为空、加载失败、资源版本变化、备用题不足：不静默替换成未验题。
- seed + 版本 + 配置复现；旋转、镜像、换色去重。

### 浏览器与交互

- 原有单击、双击、拖动、长按、清除、显示解、扣星、胜负与下一关不退化。
- “重玩”题目不变；刷新不丢本局；辅助通关不计作独立完成样本。
- 提示层可以关闭；背景事件不穿透；缩放、滚动和移动端安全区不遮挡证据。
- 第一／二层关闭后可自行推进，完整解释可直接展开；记录最高提示层级，不把重新打开第一层累计为更深求助。
- 前后台切换和主动暂停的时长记录正确；前台静止思考不被自动扣除或触发强制帮助。
- 检查 390px 手机宽度与桌面宽度下的 7×7、9×9、12×12。最终是否作为手机正式支持，以实际设备验收为准。
- 12×12 若触点不足，不得靠更小的文字勉强通过；可降低在窄屏主线的出现频率或另行设计缩放。
- 中文色名覆盖现有 12 色；行列编号、全角标点、中英数间距确定性格式化。

### 性能初始预算

在约定测试设备和浏览器上记录 P50/P95，而不是只报最快一次：

- 已缓存题切关目标 P95 ≤100ms，不包含人为过场。
- 基础／联合锁提示目标 P95 ≤150ms。
- 限定反证目标 ≤500ms；超出转异步、可取消，并明确状态。超时不是“没有解”。
- 运行时不得因产题长循环造成持续主线程阻塞；预生成预算与在线交互预算分别记录。

这些是待验证预算。如果为达到性能需要改变规则覆盖或评分，应显式更新分析版本及关卡验收，不能静默减少能力。

## 12. 后续可以做，但不并入首版

1. **按技巧温和调整**：固定节奏试玩通过后，才考虑按具体技巧的多题表现，最多微调下一道新题目标 ±5 分，并保持本周期峰值和缓和约束。详见下表。
2. **按需练习**：玩家明确选择后，可练“联合占行列”或“短反证”，与主线进度分开。
3. **动态新题**：关卡库与 Worker 产题结合；必须复用同一入库审计，不接受临时无证据题。

首版不增加体力、广告、金币或强制限时；不引入 LLM 现场编造提示；不做跨设备账号系统。

| 观察到的表现 | 后续调整方向 | 判断限制 |
| --- | --- | --- |
| 多道不同题中独立完成同技巧挑战 | 增加一个维度：入口隐蔽程度或关系组合 | 无提示不等于已掌握；结合错误和简短理由核验，不因单次连胜提升 |
| 多次对同技巧展开完整解释 | 下一题给同技巧、布局更清楚的练习 | 提示是学习行为，不直接视为失败 |
| 推理正确但操作慢或误触 | 检查触点、标记操作和反馈 | 不据此降低逻辑难度 |
| 一道挑战失败 | 保留同题重玩和分层帮助 | 单次失败不更新能力结论 |
| 多次卡在同一关系并主动求助 | 下一题减少一个难度维度，复习该关系 | 需结合求助和完成情况；前台无点击不单独触发 |

如实施个性化，候选状态可使用“尚未观察／需要练习／独立完成过／多题稳定”等描述，具体更新阈值另做校准，不能用一次游戏得分冒充心理能力测量。玩家可主动选择“轻松一点／挑战一下”，仅影响下一道新题；当前 puzzleId、答案和关系固定，所有调整记录原因并保留内容版本。

## 13. 完成定义

完成这次改造需要同时满足：

- 至少一套可稳定游玩的 30 关波浪主线，后续按同标准扩展 100 关。
- 每关形态与其角色相符：短挑战有精彩关键证明，较长挑战有分离瓶颈与突破后推进；不统一堆卡点。
- 教学先于新技巧挑战，挑战后有复用该技巧的清晰短题；扩展模板仍满足跨周期节奏约束。
- 原始单格在教学期后退出，但关卡仍有可解释入口。
- 小棋盘能产生真正的挑战，大棋盘不会因尺寸自动判为难。
- 每条正式提示有可信、可回放证明，误标不再污染结论。
- 共享规则引擎服务于生成审计、难度评估与玩家提示。
- 同题重玩与刷新恢复可靠，产题失败不静默降标。
- 数学和交互测试通过，并完成单关体验、跨关学习迁移与分层提示的真人试玩校准；不能仅凭时长或连胜认定成功。

实施优先级：**正确性与证据 → 真正难题的产出 → 波浪编排 → 提示展示 → 真人校准**。先完成 30 关可玩闭环，再扩大内容数量。

## 14. 研究依据与设计假设的边界

本节整理本次讨论中已经核对的研究来源。它们为体验方向提供依据，不直接证明本计划的关卡间隔、评分权重或通关率最优。

- 多巴胺参与奖励预测误差与学习，但没有依据从本游戏的继续点击或通关时长推算玩家多巴胺分泌。本项目采用可观察的体验和学习指标。[Schultz，2016，奖励预测误差信号](https://www.nature.com/articles/nrn.2015.26) 。
- 游戏研究发现，感受到的能力感、自主性与游戏享受及继续游玩的动机有关。本方案据此提出“学会 → 独立发现 → 挑战 → 熟练反馈”的产品假设，需要本游戏试玩验证。[Ryan、Rigby 与 Przybylski，2006，游戏动机研究](https://www.rochester.edu/warner/lida/wp-content/uploads/2022/11/02bfe513dd59366750000000.pdf) 。
- “85% 规则”研究在特定二元分类学习算法条件下讨论最佳训练准确率，不能直接套用为本游戏的最佳通关率或成瘾率。[Wilson 等，2019，学习难度研究](https://www.nature.com/articles/s41467-019-12552-4) 。

4～6 关峰值间隔、长短挑战形态、评分权重和温和调整范围均为本产品的初始设计选择；保持唯一解、可信提示及内容版本等属于工程验收条件。二者分开记录，试玩结果可以修订设计参数，但不能降低正确性门槛。
